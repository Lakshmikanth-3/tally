# Tally — Project Report

**A shop's verified revenue becomes a short bond. Underwritten in private, priced in public, settles itself.**

Built for ETHOnline 2026 — sponsor tracks: Hedera, Chainlink, The Graph.
Repository: https://github.com/Lakshmikanth-3/tally
Report generated: 2026-09-10

---

## 1. What this is

A shop's real revenue is read once, privately, inside a Chainlink Confidential
Workflow's TEE (Trusted Execution Environment). Only a verdict — approve or
decline, and a coupon rate — ever leaves the enclave. That verdict becomes
the coupon rate on a bond issued through Hedera's Asset Tokenization Studio
(ATS). Coupons and redemption fire on Hedera Scheduled Transactions, with no
keeper bot watching a calendar. Every issuer's repayment history is indexed
by a Graph subgraph into a public, queryable performance register — so a
business's credit is earned by repayment, not asserted by paperwork.

**The pitch, in one breath:** *"Chainlink reads the revenue privately and
sets the rate. Hedera issues the bond and pays it back on its own schedule.
The Graph makes every issuer's track record public and comparable — so
credit is earned, not gatekept."*

## 2. Governing constraint: zero mocks, zero fixtures

This project was built under one hard, repeatedly-enforced rule: **no
mocked data, no fixtures, no simulated infrastructure, anywhere in the
product.** Every number, every transaction, every contract call in the
actual system is real — real Hedera testnet transactions, a real Stripe
Connect integration, a real deployed subgraph, real Chainlink CRE logic.

The one deliberate exception is **disclosed, not hidden**: one demo business
("Corrado's Deli") uses synthetic revenue data, generated by an explicit
one-off script, flagged `is_demo` in the database, and displayed with a
visible **"Synthetic demo data — not a real business"** badge everywhere its
revenue appears in the console. Everything *downstream* of that revenue
number — underwriting, bond issuance, settlement, subgraph indexing — runs
identically whether the input came from a real Stripe account or this one
disclosed synthetic seed. Nothing is silently faked; nothing is mislabeled.

## 5. What's real and verified, subsystem by subsystem

### 5.1 On-chain infrastructure (Foundry contracts)

- **`SettlementAnchor.sol`** — emits one standardized `LifecycleEvent`
  (issued/coupon/resale/redeemed/defaulted) regardless of issuer, so a
  single subgraph query pattern works identically across every business.
  Access-controlled: only a designated `recorder` address can anchor events.
- **`SecondaryMarket.sol`** — a minimal resale venue for issued bonds. Fill
  orders are compliance-gated by the underlying ATS token's own transfer
  restriction — an unverified counterparty's fill genuinely reverts on-chain
  (this contract doesn't duplicate that check, it relies on ATS's real
  enforcement being the source of truth).
- **8 passing Foundry tests**, including the load-bearing ones: an
  unverified counterparty's `fillOrder` call reverts with the real ATS
  revert reason, and (added when the bid-fill payout direction was fixed)
  a bid's payout goes to its maker rather than whoever fills it, and reverts
  if the maker isn't a verified holder.
- **Deployed twice, deliberately:**
  - Hedera testnet (the real product deployment): `SettlementAnchor`
    `0.0.10501789`, `SecondaryMarket` `0.0.10501801`
  - Ethereum Sepolia (`0xFa5FE1d656B9d2D382D9Fc717Bd22c1f79Add9f4` /
    `0x3d56CC4eEFe9c51957F2B34096e29Ef0B4fc84d4`, deployed from the same
    custodian account as the Hedera copy but not at the same CREATE address,
    since that depends on the account's nonce on each chain) — purely
    because Subgraph Studio does not support Hedera as an indexable network
    (verified against their own supported-networks list). See
    `FEEDBACK/THEGRAPH.md`.

### 5.2 The Graph subgraph

- Deployed live: https://thegraph.com/studio/subgraph/tally-register

- Schema: `Bond`, `LifecycleEvent`, `IssuerStanding` — the same shape for

- **Verified live** (2026-09-10): a real query against the deployed endpoint

### 5.3 Chainlink CRE confidential workflow (`cre/tally-cre`)

- Real TypeScript CRE project, using `cre.handlerInTee` to run underwriting
  logic inside a TEE.
- Fetches a business's real trailing-90-day revenue snapshot from the
  console's own authenticated API (`REVENUE_API_TOKEN` bearer secret,
  fetched via `runtime.getSecret()` inside the enclave).
- Applies real underwriting logic (revenue threshold, volatility ceiling,
  history-length check) and returns only the verdict — approve/decline plus
  coupon rate in basis points.
- **Verified live via simulation** (`cre workflow simulate underwriting
  --target staging-settings --non-interactive --trigger-index 0`), most
  recently: `APPROVED (bps=428, reason=0)` for Corrado's Deli, and a genuine
  `INSUFFICIENT_HISTORY` decline for a freshly-registered business with no
  revenue history — both outcomes are real, not scripted.
- **Not yet live-deployed**: Confidential Workflows are gated behind a
  Chainlink private-beta deployment-access review. A request was submitted
  (`cre account access`) and is pending manual review with no stated SLA —
  see `FEEDBACK/CHAINLINK.md`. The workflow logic itself is complete and
  simulation-verified; only the live TEE deploy is outstanding.

### 5.4 Hedera Asset Tokenization Studio integration (`packages/ats-client`)

This was the deepest and most debugging-intensive part of the project. The
ATS SDK (`@hashgraph/asset-tokenization-sdk` v8.0.0) has no documented path
for signing from a plain Node.js backend — every state-changing call is
gated behind a real browser context (`window.ethereum`, real Web Crypto,
real `window` object). Rather than fall back to a third-party custodial
signing service, Tally built its own solution:

- **A real headless-browser signer** (`browser-runner/`) — Playwright drives
  real headless Chromium, with a minimal injected EIP-1193 `window.ethereum`
  backed by a real `ethers.Wallet` (Tally's own custodian key). The SDK runs
  completely unmodified, exactly as designed for a real browser wallet — the
  only difference is the wallet is programmatic, not a human clicking
  MetaMask. Tally is the custodian: businesses never touch a wallet.
- **Real bond issuance, verified live end-to-end**: `Bond.create` +
  `FixedRate.setRate` (the single-call `Bond.createFixedRate` path is broken
  in this SDK version — discovered and worked around), with the required
  post-issuance role grants (`_INTEREST_RATE_MANAGER_ROLE`) and a real,
  checksummed ISIN (the deployed Factory contract validates a genuine ISO
  6166 Luhn checksum on-chain, undocumented in the SDK).
- **Real bond redemption, verified live end-to-end**: `Bond.
  fullRedeemAtMaturity`, gated behind three more real access-control checks
  discovered one revert at a time — `_CONTROLLIST_ROLE`, the token's
  whitelist-mode control list, and a real per-account KYC status check. The
  KYC grant itself is real: a self-signed ECDSA verifiable credential
  (`kyc.ts`, using `@terminal3/ecdsa_vc`), not a stub or a skipped check.
- Every one of these gaps is documented in detail, with the exact revert
  selector decoded against the contract's real ABI, in
  `FEEDBACK/HEDERA.md`.
- **Real issued/redeemed bonds on Hedera testnet** (example token IDs from
  live testing): `0.0.10425260`, `0.0.10425775` (issued via the console
  API), `0.0.10425352` (issued, matured, and successfully redeemed).

### 5.5 No-keeper settlement (`packages/scheduler`)

- Coupon payments and redemption anchoring are armed as real Hedera
  `ScheduleCreateTransaction`s with `setWaitForExpiry(true)`.
- **Verified live, multiple times**: an armed schedule executes itself at
  expiry with zero keeper, cron job, or bot watching it. On-time/late status
  is derived from the mirror node's real consensus timestamp of the
  execution versus the bond's maturity — never a hand-set boolean.

### 5.6 Console (`apps/console`)

- Next.js 15 app: business registration, real Stripe Connect OAuth,
  real revenue computation, and a full underwriting → bond-issuance UI wired
  to every subsystem above.
- Styled with a real, cohesive visual design pass (typography, color
  tokens, cards, buttons) — not the bare unstyled HTML it started as.
- **Verified live**: registering a fresh business shows an honest `$0.00`
  revenue and a genuine `INSUFFICIENT_HISTORY` decline when underwriting is
  attempted; Corrado's Deli (disclosed synthetic data) shows a real approved
  verdict and a real issued bond with clickable HashScan links.
